# Ad Astra paid-access release candidate

The former shared-budget placeholder is replaced by a mandatory server-only admission call in `api/ask.js`. A verified session and Redis quota alone no longer authorize model spending. The reviewed internal backend candidate implements live-session verification, server-owned identity/tenant/subscription binding, current Stripe entitlement checks and atomic shared-budget reservation. No approval boolean grants access.

The client accepts only the pinned Supabase function path over HTTPS, a dedicated protected server credential, exact bounded JSON and a fresh response bound to the request hash. Entitlement denials return 403, replay denials 409, tenant capacity denials 429, and ambiguous/configuration/provider failures 503 without sending an OpenAI request or activity stream. No caller-selected tenant, plan, price, amount or entitlement is sent. Provider failures never retry or release uncertain reservations.

The internal companion is in `Centauri-corp/ad-astra-internal-source`: `supabase/functions/astra-customer-budget/` and migration `20261111032159_customer_paid_access_bridge.sql`. Deployment order and the acceptance matrix are in its `docs/customer-paid-access-bridge.md`. Both exact commits require review as one candidate; a public-only deployment cannot complete this integration.

Browser QA now isolates every route in a new page. The old harness reused a document across protected routes and subsequent public routes, allowing delayed navigation to interfere with the next `goto`. The public-source scan blocks external provider traffic and checks the SDK-unavailable, fail-closed view of all routes. Separate synthetic anonymous-session checks exercise the actual knowledge-to-platform redirect and delayed-navigation isolation. These checks are not live sign-in acceptance; that remains protected customer QA. Each page is closed before the next starts; no navigation assertion, route, viewport or accessibility scan is skipped or retried. An eight-minute execution limit and per-route navigation/accessibility/screenshot checkpoints turn a stalled run into explicit failed evidence. CI retains that evidence and screenshots for seven days. Local success does not substitute for the hosted CI result on the final commit.

This change does not approve or activate production, subscriptions, CRM delivery, outreach or indexing. Real test-mode payment/webhook, hosted Clerk recovery/logout, two-tenant data access, a bounded provider response, cancellation/revocation, CRM acknowledgment and support/rollback receipts remain required. Tahira must approve the exact final candidate independently. The release owner then records scoped authorization and uses controlled staging/promotion. Search-property verification and approved-page indexing remain separate.
