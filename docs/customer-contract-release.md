# Website/customer contract correction release

This candidate implements the seven-step architecture correction plan through
controlled PR #38 over the selected PR #36 base. It is not a record of public
activation. The companion source and exact commit are pinned in
`config/production-release-source.json`.

1. **Interface ownership:** gateway v2 identifies its real private receiver. Public Clerk QA has its own workflow and protocol; internal Supabase QA cannot stand in for it. Hosted subscription receiver v12 source is preserved in the private companion.
2. **Onboarding:** an explicit empty-body `provision` action creates a verified subject-owned workspace through the private receiver. Existing-account password/MFA linking remains a separate migration path. The UI only offers setup when source and provider release conditions permit it; setup itself does not purchase a subscription.
3. **Execution/accounting:** a request-hash-bound paid admission carries request ID, reservation, agent/mode, idempotency and environment to the receiver. That receiver derives customer tenancy, redeems once, enforces a private model/output/cost policy, validates provider provenance and records correlated usage. Invoice cost remains unverified until independent billing evidence exists. Unpaid/replayed requests consume abuse capacity rather than model-spend capacity. Session verification checks online revocation without reserving budget. A domain-separated workload credential can reuse the existing protected bridge root without another copied secret.
4. **Customer continuity:** all seven catalog agents survive browser selection, sign-in return, submission and answer events. Research/visual profiles in this release are text planning/briefs; media ingestion and retrieval are not available. Product mode links resolve actual intelligence sections.
5. **Graphics:** visible primary art follows its registry independently of social metadata. Decoded types/dimensions/provenance, held origins, current source bytes, policy-bound visual hashes and hashed route/viewport review artifacts are checked. Mobile crop/source sizing is corrected. The current 1672px master still cannot provide native desktop retina detail; no upscale is represented as a native high-resolution master. Owner aesthetic/rights acceptance remains pending.
6. **Lifecycle:** the private companion contains tenant/subject-scoped lifecycle SQL, an adapter and provider reconciliation worker, tested on synthetic PostgreSQL. Production eligibility/hold policy, provider permissions, export delivery, support ownership and actual downstream acknowledgments still need operating evidence. The four required privacy/terms/security/support routes remain recorded as incomplete; this candidate does not invent legal terms or a support channel.
7. **Release:** current code stays closed to new live AI, billing, indexing and outreach while the exact candidate is tested/reviewed. Use the existing release ledger, independent reviewer and scoped release authority. Do not turn local conformance, browser screenshots or sample data into hosted acceptance receipts.
